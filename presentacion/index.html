API Gemini

Google AI Studio
modelo de lenguaje

  • La petición sale del navegador por HTTPS con la clave del visitante.
  • La respuesta vuelve como eventos SSE y se pinta al instante.
  • El servidor (CloudPanel) solo entrega los archivos: no procesa la conversación.

Autenticación

La API key

  • Se obtiene gratis en aistudio.google.com/apikey.
  • Se guarda en localStorage, solo en el navegador del visitante.
  • Nunca se escribe en el HTML ni en el JavaScript.
  • Cada persona que entra usa su propia clave.
Si la clave se publica en el código, cualquiera puede leerla con «Ver código fuente» y gastar tu cuota de IA.

La conexión

La petición HTTP

POST https://generativelanguage.googleapis.com/v1beta/models/
     gemini-flash-latest:streamGenerateContent?alt=sse&key=•••
Content-Type: application/json

{
  "contents": [
    { "role": "user",  "parts": [{ "text": "Hola" }] },
    { "role": "model", "parts": [{ "text": "¡Hola!" }] }
  ],
  "generationConfig": { "temperature": 0.7 }
}

El historial se envía completo en cada petición: ahí está la «memoria» del chat.

Streaming

La respuesta llega por trozos

  • Google responde con Server-Sent Events.
  • Cada línea data: {...} trae un fragmento de texto.
  • Se lee con ReadableStream y TextDecoder.
  • La interfaz se actualiza sin esperar el final.
// cada evento SSE
data: {"candidates":[{"content":
  {"parts":[{"text":"Hola"}]}}]}

// leer el stream
const reader = res.body.getReader();
const decoder = new TextDecoder();

decoder.decode(value, { stream: true });

Resultado: el texto aparece mientras se genera, no después.

Se guarda como model

  • Los roles alternan: user → model → user.
  • Más historial = mejor contexto, pero más tokens por petición.
  • Por eso se recorta la ventana y se empieza siempre por un mensaje de usuario.

Robustez

Qué pasa cuando algo falla

400 clave o petición inválida 403 acceso denegado 404 modelo retirado 429 cuota agotada 503 modelo saturado
  • Los errores se traducen a mensajes claros, no a JSON crudo.
  • Botón Reintentar y botón Detener (AbortController).
  • Si el modelo da 503 o 404, la app prueba otro automáticamente.

Seguridad y límites

Lo que hay que tener claro

Bien resuelto

  • Clave fuera del código fuente.
  • Cada visitante usa la suya.
  • HTTPS en el despliegue.
  • Sin backend que atacar.

Con cuidado

  • La clave es visible en DevTools.
  • No vale para producción multiusuario.
  • La IA puede inventar datos.
  • La calidad depende del modelo y la temperatura.
Para producción: mover la llamada a un backend que guarde la clave en el servidor y actúe de proxy.

Conclusiones

Lo que aprendí

  • Una API es una URL, unos datos y una autenticación.
  • El streaming convierte una espera en una conversación.
  • El historial es la memoria del chat.
  • Errores y seguridad son parte del proyecto, no un extra.
